# Implementation Plans

An impl plan is tactical: the spec says *what*, the plan says how a change lands, what it touches and how it is verified. A plan is named `{issue}-{slug}.md` after its feature, written on the feature's branch, and lands in the pull request with the code. Mission briefs live in [`briefs/`](briefs/README.md). After shipping, delete small-feature, bug-fix and routine-refactor plans; keep only important records in [`archive/`](archive/) under the [archive policy](../README.md#archive-policy), after folding decisions that outlive the work into [`../arch/`](../arch/).
