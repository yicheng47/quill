The failed isolation check occurred on the first real Lookup in the original discovery configuration. After capturing process ownership and the warning, QA stopped Quill's app-server and ran no further model turns on this candidate. An outer macOS filesystem guard prevented Electron's own sandbox from initializing. Applying the guard to the Codex child through an isolated discovery launcher allowed UI checks without further writes to the shared home, but Ready remained unavailable. Redirecting SQLite state and logs and disabling bundled skills still returned an operation-not-permitted error under the strict guard. The coder's separate isolated repro identified Codex's read/write open of an existing `installation_id` during startup.

The two original development profile trees and the development log tree were moved to private same-volume scratch before the launch. iCloud Sync showed Off on the fresh QA profile and stayed off throughout. After the final quit, QA moved disposable fixtures to scratch and restored the original trees. Every file matched the pre-run byte hash, and modes, ownership and symlink targets matched the manifest. Verified that port 1430, the candidate Electron processes and the Quill-owned app-server were gone. No installed Quill files were used. `sync-off.jpg`, `restoration-30a9b68.txt`.
